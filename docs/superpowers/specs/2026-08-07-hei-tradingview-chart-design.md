# HEI TradingView 式 K 线查看器设计

## 目标

把现有 HEI/USDT 静态 K 线页改为 TradingView 式本地查看器。用户可以直接在图表内拖动、缩放和查看十字光标数据，并能够逐步浏览本地 Feather 文件中的完整历史，而不是通过外部滑条切换固定切片。

## 范围

- 数据源保持为 `user_data/data/binance/futures/HEI_USDT_USDT-*-futures.feather`。
- 支持 `1m`、`15m`、`1h`、`2h`、`4h`、`1d`。
- 显示蜡烛图、成交量和十字光标 OHLCV。
- 支持鼠标拖动、滚轮缩放、时间轴缩放、价格轴缩放和触控拖动。
- 默认打开 `15m`，显示最近一段数据。
- 向左浏览接近已加载数据边界时，自动读取更早的 K 线。
- 提供回到最新行情的按钮。
- 本次不加入技术指标、画线工具、下单功能或实时 WebSocket 推送。

## 架构

采用一个无额外 Web 框架依赖的本地 Python 服务：

1. 服务端使用 Python 标准库 HTTP 服务，按需读取 Feather 数据。
2. `/` 返回图表页面。
3. `/api/candles` 接收周期、截止时间和数量，只返回当前视窗所需的历史块。
4. 前端使用 TradingView Lightweight Charts，首次载入最近数据；当用户拖到左侧边缘时请求更早数据，并将新旧数据按时间去重、排序后更新图表。
5. 图表视窗由 Lightweight Charts 原生管理，代码不再通过外部滑条持续重设可见范围。

这种方式不会一次把约 78 万根 1 分钟 K 线塞进 HTML，也能逐步访问完整历史。

## 交互设计

- 顶部只保留交易对、周期按钮、当前十字光标 OHLCV、已加载时间范围和“回到最新”按钮。
- 在绘图区按住鼠标左键水平拖动历史。
- 滚轮缩放时间轴；拖动底部时间轴改变 K 线密度。
- 拖动右侧价格轴调整纵向比例。
- 图表接近左边界时显示轻量的“正在加载更早数据”状态；请求失败时显示错误，但保留当前图表可用。
- 切换周期时清空当前缓存并载入该周期最近数据。

## 数据规则

- 服务端只允许六个明确列出的周期，不能用请求参数拼接任意文件路径。
- 每批数据严格按时间升序返回。
- 重复时间戳在服务端或前端合并时去重。
- 仅展示 Feather 中已经保存的已完成 K 线，不构造未来或未完成 K 线。
- API 返回 `has_more`，让前端知道是否已到历史起点。
- 单次读取设置上限，避免异常请求拖垮浏览器或服务。

## 文件规划

- 新增 `scripts/serve_hei_kline_chart.py`：本地服务、数据查询和页面模板。
- 新增对应测试，覆盖参数校验、时间切片、排序去重、历史边界和页面关键交互配置。
- 旧的 `scripts/create_hei_kline_chart.py` 与旧 HTML 在新查看器验收后再删除，避免未验证前丢失可用产物。

## 运行方式

优先提供直接运行命令，也提供基于现有 Freqtrade 镜像的 Docker 命令。服务默认只监听本机地址；如 Docker 运行需要端口映射，则显式监听 `0.0.0.0`。

## 测试与验收

自动化验证：

- 不允许未知周期和路径穿越输入。
- 初始请求返回最新一批数据。
- 带 `before` 的请求只返回该时间之前的数据。
- 返回值升序、无重复且不超过数量上限。
- 到达最早数据时 `has_more` 为假。
- 页面不包含旧位置滑条，并启用原生滚动、缩放和历史加载监听。

人工验收：

- 打开页面后 K 线彼此可辨认，不挤成一团。
- 鼠标拖动能连续浏览历史，滚轮能平滑缩放。
- 拖到左侧后自动出现更早 K 线，当前视窗不会跳回最新位置。
- 周期切换、十字光标和成交量正常。
- `1m` 可以逐步浏览到本地数据起点，且初次打开无需加载全部历史。
